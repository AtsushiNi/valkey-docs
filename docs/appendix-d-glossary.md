# 付録 D. 用語集

本文に出てくる、Valkey と ElastiCache に固有の用語です。一般的な IT の用語（TLS、VPC など）は含めていません。

## 表記のルール

- 一般的な技術用語はカタカナで書き、その用語を説明している箇所で英語を括弧で添えます。
- 次のものは英語のまま書きます。
  - 製品名・固有名詞（Valkey、ElastiCache、redis-py など）
  - データ型の名前（String、Hash、Set、Sorted Set、List、Stream）
  - コマンド名（`SET` など。大文字で、コードとして書く）
  - メトリクス名、設定のパラメータ名

## 用語

| 用語 | 英語 | 意味 | 詳しく |
|---|---|---|---|
| アクセス文字列 | access string | ユーザーごとに、使えるコマンドとキーを決める文字列 | 15 章 |
| アトミック（不可分） | atomic | 途中でほかの処理が割り込まず、全部が一度に行われること | 02 章・06 章 |
| インメモリ | in-memory | データをディスクではなくメモリに置くこと | 01 章 |
| エビクション | eviction | メモリの上限に達したときに、キーを自動で消すこと | 11 章 |
| エンコーディング | encoding | データ型の内部での持ち方（listpack、hashtable など） | 03 章・04 章 |
| エンドポイント | endpoint | 接続先のアドレス（DNS 名） | 08 章・14 章 |
| キー | key | 値を取り出すための名前 | 02 章 |
| キー設計書 | — | キーのパターン、型、中身などを記録した文書（本資料での呼び方） | 05 章 |
| キーバリューストア | key-value store | キーと値の組を保存し、キーを指定して読み書きするデータベース | 01 章 |
| クラスター | cluster | データを複数のシャードに分けて持つ構成 | 13 章 |
| クラスターモード | cluster mode | クラスターとして動かすかどうかの設定 | 13 章・14 章 |

| コネクションプール | connection pool | 接続を使い回すための仕組み | 08 章 |
| コピーオンライト | copy-on-write | スナップショットの作成中に変更されたデータを、別にコピーする仕組み | 11 章 |
| 再同期（全体の同期） | full sync | レプリカに、データ全体を送り直すこと | 13 章 |
| サービスの更新 | service update | ElastiCache が提供する、セキュリティの修正などの更新 | 18 章 |
| シャード | shard | クラスターの中で、データの一部を受け持つ単位（プライマリとレプリカの組） | 13 章 |
| シリアライズ | serialization | オブジェクトを、保存できる形（JSON など）に変換すること | 03 章 |
| 世代 | generation | 全件の入れ替えで作る、データ一式のこと（本資料での呼び方） | 09 章 |
| 耐久性の機能 | durability | 書き込みを複数の AZ のログに記録し、失わないようにする ElastiCache の機能（Valkey 9.0 以降） | 12 章 |
| 断片化 | fragmentation | 解放されたメモリが細切れになり、再利用されないまま残ること | 11 章 |
| データストア | data store | データを保存して読み出すための仕組み。本資料では、キャッシュとは区別して使う | 01 章 |
| トランザクション | transaction | `MULTI` 〜 `EXEC` で、複数のコマンドを不可分に実行する仕組み（ロールバックはない） | 06 章 |
| 二次インデックス | secondary index | 主キー以外の条件で探すために、自分で作る索引 | 04 章・05 章 |
| ノード | node | Valkey が動く1台のサーバー | 13 章・14 章 |
| ノードタイプ | node type | ノードの性能の種類（`cache.r7g.xlarge` など） | 14 章 |
| ノードベース | node-based | ノードタイプと数を自分で決める ElastiCache の構成 | 14 章 |
| ハッシュスロット | hash slot | キー名から計算される 0〜16383 の番号。どのシャードに置くかを決める | 13 章 |
| ハッシュタグ | hash tag | キー名の `{}` で囲んだ部分。その部分だけでハッシュスロットを計算する | 05 章・13 章 |
| パイプライン | pipeline | 複数のコマンドを、応答を待たずにまとめて送ること（不可分ではない） | 06 章 |
| バックフィル | backfill | インデックスを作ったときに、既存のキーを読み込むこと | 07 章 |
| パラメータグループ | parameter group | ノードベースの ElastiCache の設定値の集まり | 14 章 |
| ビッグキー | big key | 要素が多すぎる、または値が大きすぎるキー | 03 章 |
| フェイルオーバー | failover | プライマリが故障したときに、レプリカをプライマリに昇格させること | 13 章 |
| プライマリ | primary | 書き込みを受け付けるノード（「マスター」とは呼ばない） | 13 章 |

| メンテナンスウィンドウ | maintenance window | ElastiCache が変更を適用する、週1回の時間帯 | 18 章 |
| 予約メモリ | reserved memory | バックアップなどのために、データ用とは別に空けておくメモリ | 11 章 |

| リダイレクト | redirect | 担当でないノードが返す「担当はあちら」という応答（MOVED、ASK） | 13 章 |
| レプリカ | replica | プライマリのデータを複製して持つノード（「スレーブ」とは呼ばない） | 13 章 |
| レプリケーション | replication | プライマリのデータをレプリカに複製すること（非同期） | 13 章 |
| 有効期限 | TTL / expiration | キーが自動で削除されるまでの時間 | 02 章 |
| ECPU | ElastiCache Processing Unit | ElastiCache Serverless の、リクエストの量の単位。転送するデータ 1 KB あたり 1 ECPU | 14 章 |
| listpack / hashtable / skiplist / intset | — | データ型の内部のエンコーディングの名前 | 03 章・04 章 |
| NoSQL | — | RDB 以外のデータベースの総称（キーバリューストア、ドキュメントデータベースなど） | 01 章 |
| RDB スナップショット | RDB snapshot | ある時点のデータ全体を書き出したファイル（リレーショナルデータベースの RDB とは無関係） | 12 章 |
| RESP2 / RESP3 | — | Valkey とクライアントの間の通信の方式 | 07 章・08 章 |
| Serverless | ElastiCache Serverless | 容量の管理が不要な ElastiCache の構成 | 14 章 |
